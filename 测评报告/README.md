## 交付规则

1. **哪部分完成写哪部分**：某核查项的检查方法/判定逻辑/证据/结论经确认并落地后，才写入对应章节文件；未完成的章节留空占位，不预填。
2. **以《配置核查作业指导书 v2.0.0》为基准**：每条的检查方法以指导书本条原文为准；工具实现与指导书不一致处，以指导书为准修正工具。
3. **交叉检查**：第 3、4 章等"条目分解不完善"的高发区，需经交叉检查（不同人复核）确认后再写入。缺口对照见 [`manual_review/第3-4章缺口对照.md`](../manual_review/第3-4章缺口对照.md)。
4. **报告字段**：每条核查项含 6 要素——
   - 编号 / 标题
   - 检查方法（分平台：Windows / 麒麟，引用指导书本条方法）
   - 判定标准（什么情况 pass / fail / manual / na）
   - 工具实现（脚本函数名 + 自动判定逻辑一句话）
   - 实测证据（真机或沙盒跑出的 detail 原文）
   - 结论（合规 / 不合规 / 需人工核查 / 不适用 + 一句话理由）
