## 4.1 应用系统软件应采取备份措施

**【检查方法】**（指导书 v2.0.0 第485页）

- Windows（Win7/WinXP）：
  - 查备份目录：`dir C:\ /ad /s | findstr /i "backup bak"`
  - 查近期备份文件：`dir D:\backup /o:-d`
  - 查定时备份任务：`schtasks` / `schtasks | findstr /i "backup bak copy"`
- 中标麒麟/银河麒麟：
  - 查备份目录与文件：`find / -type d -name "*backup*"` / `find / -type f -name "*.bak" -o -name "*.tar.gz" -o -name "*.sql.gz"`
  - 查定时备份任务：crontab / `/etc/cron.*`

**【判定标准】**
- pass：检测到应用系统/数据库/操作系统任一层面的有效备份措施（备份文件存在且时间近期，或存在定时备份任务）
- fail：无任何备份文件、无定时备份任务
- manual：检测到备份相关痕迹但无法确认有效性，或需结合业务系统自身备份功能人工确认

**【补充说明——多层核查】**
本条备份可能涉及三个层面，不可只查 OS 层：
1. **应用系统本身**的备份功能（应用自带导出/备份按钮、备份配置文件）
2. **数据库**的备份策略（mysqldump/达梦dmap/金仓sys_dump 计划任务、binlog）
3. **操作系统**的定时备份任务（schtasks/cron + 备份目录/文件）

任一层确认有效即视为满足；OS 层未发现不能直接判 fail/na，需结合另外两层人工确认。

**【工具实现】**
- Kylin：`check_kylin.sh` 第4章 `add_manual_checks()` 中 4.1 —— 已标 manual，detail 写明三层备份核查方法（应用自身备份/数据库备份/OS定时任务），OS层具体备份文件检查在 4.32（`check_4_32_domesticsoftware`，该函数实际查备份文件与cron任务）。
- Windows：`check_xp7.vbs` 第4章 4.1 —— 同步对齐中。

**【实测证据】**（2026-08-08 沙盒 Git Bash）
- 4.1 判定：manual，详情"应用系统备份可能涉及三层…OS层备份详见4.32，其余两层需人工核查。"

**【结论】** 需人工核查 —— OS层备份检查已并入4.32，应用自身备份功能与数据库备份策略需人工确认。

## 4.25 应具有对所有访问行为和管理行为的日志审计功能，审计日志应至少保留180d

**【检查方法】**（指导书 v2.0.0）

- 中标麒麟/银河麒麟：
  - 审计服务状态：`systemctl status auditd` 或 `systemctl status rsyslog`
  - 日志文件：`ls -lh /var/log/auth.log`
  - 日志轮转180天：`grep -r "rotate|maxage|180" /etc/logrotate.d/ /etc/logrotate.conf | grep -i audit`
  - 查询工具：`which ausearch` / `which aureport`

**【判定标准】**
- pass：auditd运行中 + 标准审计日志文件存在 + logrotate配置≥180天
- fail：未检测到auditd或rsyslog/syslog-ng
- manual：服务在运行但日志留存是否达180天/审计规则覆盖面无法确认

**【工具实现】** `check_kylin.sh` → `check_4_25_logaudit()`：查 auditd/rsyslog 服务状态、/var/log/audit/audit.log 等日志文件、logrotate 中 audit 的 rotate 次数（≥26周≈180天）、ausearch/aureport 可用性。

**【实测证据】**（2026-08-08 沙盒 Git Bash）
- 判定：不合规（fail）
- 详情：未检测到auditd或rsyslog/syslog-ng；日志文件:未找到标准审计日志文件；轮转:；查询工具:无ausearch/aureport。

**【结论】** 不合规 —— 沙盒环境无审计服务与日志文件。真实麒麟机上若 auditd 运行且 logrotate 配置≥180天则判 pass。
